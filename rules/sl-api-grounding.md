# SL API 근거 확인

SL 코드에서 FEGate API 를 부를 때 적용함. 없는 함수, 틀린 인자, 잘못 이해한 동작을 코드에 쓰기 전에 막는 것이 목적임.

## 볼 곳

| 알고 싶은 것 | 볼 곳 |
|---|---|
| 함수가 있는지, 시그니처, 동작 | `fegate_api/*.h` 의 `HELP_FUN` 블록. `sl-api-lookup` 스킬로 블록만 뽑음 |
| 구조체 멤버 | `fegate_api/structs.h` 의 `HELP_STRUCT` 블록. 같은 스킬로 뽑음 |
| 상수 값 | `fegate_api/defines.h`. 같은 스킬로 뽑음 |
| 호출 패턴 | `fegate_api_exam/` 의 .sl 예제. 스킬 출력에 예제 경로가 나옴 |
| 시그니처로 안 보이는 함정 | `sl-report-fail` 스킬의 `failures.md` |

헤더가 정본임. 예제와 다른 문서가 헤더와 다르면 헤더를 따름.

## 쓰기 전 확인

1. 존재: 헤더에서 이름을 찾음. 없으면 그 함수는 없음. 스킬이 보여 주는 비슷한 실제 이름 중에서 고름.
2. 시그니처와 동작: 인자 개수, 타입, `ref` 인자를 확인함. `@brief` 와 `@return` 으로 실제 동작을 확인함. 매개변수 모양으로 동작을 추측하지 않음. 예: `matEmpty(ref type ary[ ][ ])` 는 행렬을 비우지 않고 비었는지 돌려줌.
3. 함정: `failures.md` 에 같은 함수나 패턴이 있는지 확인함.

확인을 끝내지 못하면 그 사실을 말함. 맞다고 단정하지 않음.

## 읽기 제한

- 헤더 파일 전체를 읽지 않음. 필요한 블록만 뽑음.
- 큰 산문 API 문서(예: `FFSAPI.md`)를 통째로 읽지 않음. 줄 범위 색인이 있으면 그 범위만 읽음.
- 예제를 그대로 복사하지 않음. 예제에도 버그가 있음(`failures.md` 의 F-004).

## 구현 후 확인

1. 새로 쓴 API 호출을 모두 헤더와 대조함. `.sl` 파일을 고치면 `sl-api-check` 훅이 자동으로 검사함. 훅이 알린 이름은 고치거나, 사용자 정의 함수라는 근거를 댐.
2. `failures.md` 항목과 대조함.
3. 새 함정을 찾으면 `sl-report-fail` 스킬로 기록함.

## 검증 한계

헤더 대조와 원장 대조는 첫 시도의 정확도를 높임. 실행 결과를 보장하지는 않음. 실제 동작은 FEGate 에서 실행해야 확인됨. 완료 보고에 FEGate 에서 사람이 확인할 항목을 적음.
