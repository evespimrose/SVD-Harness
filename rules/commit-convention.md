# 커밋 메시지 규칙

git 커밋 메시지를 만들 때 적용함.

## 형식

```
말머리: 제목
```

말머리, 콜론, 공백 한 칸, 제목 순서임. 본문은 빈 줄 다음에 씀. 대부분의 커밋은 제목 한 줄로 끝남.

## 말머리

| 말머리 | 쓰는 경우 |
|---|---|
| `feat` | 새 기능 |
| `fix` | 버그 수정 |
| `refactor` | 동작을 바꾸지 않는 구조 변경 |
| `docs` | 문서만 바뀐 커밋 |
| `chore` | 설정, 빌드, 의존성 같은 기타 변경 |
| `secure` | 보안 수정 |

코드 변경에 문서 수정이 함께 들어가면 코드 쪽 말머리를 씀.

## 제목

- 한국어로 씀. 코드 식별자는 원문 그대로 씀.
- 무엇을 바꿨는지 씀. 끝에 마침표를 찍지 않음.
- 50자 안쪽으로 줄임.
- UI 와 기능 분리 작업은 무엇을 어디로 옮겼는지 씀. 예: `refactor: 절점 집계를 bt_count 콜백에서 count_free_nodes 로 분리`

## 본문

- 제목과 diff 만으로 알 수 없는 제약이 있을 때만 씀. 1~2줄로 씀.
- 작업 과정, diff 재설명, 꾸밈말을 쓰지 않음.
- 이슈를 닫으면 마지막 줄에 `Closes #번호` 를 씀.

## 금지

- AI 도구 서명 줄(`Co-Authored-By: Claude ...`, `Generated with ...`)을 넣지 않음.
- 사용자가 요청하지 않으면 커밋하지 않음. 커밋 전에 메시지 초안을 보여 줌.

## 예

```
fix: 0 좌표 행이 파싱에서 빠지는 문제 수정
feat: 선택한 요소의 법선 방향으로 그룹 생성
refactor: 파일 대화상자 호출을 UI 콜백으로 이동
```
