# sl-report-fail

함정 원장은 이 스킬 폴더의 `failures.md` 임. SL 코드를 쓰기 전에 읽고, 새 함정을 찾으면 아래 절차로 추가함.

## 기록할 때

- 헤더에 없는 함수를 썼을 때
- 인자 개수, 타입, `ref` 를 틀렸을 때
- 컴파일은 되지만 결과가 틀렸을 때
- 사용자가 FEGate 컴파일 오류나 실행 오류를 알렸을 때

## 절차

1. 심각도를 정함. `API`, `BEHAVIOR`, `INTENT` 중 하나임. 정의는 `failures.md` 머리에 있음.
2. 중복을 확인함. 같은 내용의 항목이 있으면 새로 만들지 않고 그 항목을 고침.
3. 올바른 방법을 검증함. `sl-api-lookup` 스킬로 헤더 선언을 확인하거나, 예제 경로나 FEGate 실행 결과를 근거로 댐. 검증하지 못한 내용은 기록하지 않음. 틀린 항목은 다음 실수를 만듦.
4. 맨 아래 주석 줄 위에 다음 번호로 추가함.

```
## F-0NN · <심각도> · <짧은 제목>

- **증상**: 오류 메시지 또는 틀린 결과
- **원인**: 왜 생겼는지
- **올바른 방법**: 검증된 방법. API 면 시그니처를 함께 씀
- **근거**: fegate_api/ 또는 fegate_api_exam/ 경로, 또는 FEGate 실행 결과
```

5. 사용자에게 추가한 항목 번호를 알림. 원장은 SVD-Harness 저장소 안에 있음. 팀이 함께 쓰려면 사용자가 하네스 저장소에서 커밋하고 공유함. 사용자가 요청하지 않으면 커밋하지 않음.
